# AutoSell collection protection, 2026-11-04

Build `231`, version `2.5.9.3`, adds a check before opening or collecting from a
LootChest when 1MB-Library AutoSell is active. The local feature branch is
`codex/lootchest-autosell-guard`. It continues the verified Oracle toolchain
source at `3fe301093b8f`; build 230 and the Paper 207 fixture remain archived.

## Finding and behavior

The baseline probe loaded the actual AutoSell `1.0.4-834` plugin, enabled a
temporary synthetic player's profile, and verified that plain LootChest
cobblestone passed AutoSell's own item eligibility check. LootChest then delivered
that sellable reward without checking AutoSell. The reproduction failed with:

```text
PROBE AutoSell ON; plain LootChest cobblestone is sellable by actual AutoSell
AutoSell ON received sellable loot without a safety check
```

The command was `LOOTCHEST_ALLOW_DIRTY=1 ./scripts/smoke-paper-26.3.py
target/1MB-LootChest-v2.5.9.3-231-CMI-j25-26.3.jar`. Baseline logs remain under
`.scratch/autosell-20261104/before-clean/20261104-154139/`. This demonstrates the
unguarded collection and sale eligibility; the probe never executes a real sale
or economy payout.

Opening is now refused with:

> You cannot open this LootChest yet because AutoSell is on. Run "/autosell toggle" to turn it off, then try again.

Missing language keys are added on upgrade while custom translations are kept.
The guard rechecks active inventory interactions, breaking, direct delivery and
marked ground-loot pickup. A pending AutoSell transaction or off-state save also
requires a retry. See [integration behavior and boundaries](../integrations.md#1mb-library-autosell).

Run from a clean local feature-branch commit:

```bash
env -u LOOTCHEST_ALLOW_DIRTY ./mvnw clean verify
python3 -m unittest discover -s scripts -p 'test_*.py' -v
env -u LOOTCHEST_ALLOW_DIRTY ./scripts/smoke-paper-26.3.py \
  target/1MB-LootChest-v2.5.9.3-231-CMI-j25-26.3.jar
env -u LOOTCHEST_ALLOW_DIRTY ./scripts/smoke-paper-26.3.py --without-integrations \
  target/1MB-LootChest-v2.5.9.3-231-CMI-j25-26.3.jar
```

The full Maven checks cover the guard's public API contract, UUID targeting,
state changes between actions, pending saves, provider failure/recovery,
off-thread refusal, language migration and release packaging. Runtime probes
exercise real registered LootChest handlers and the actual AutoSell provider
with synthetic Java and Bedrock identities, including renamed display names.
They verify opening, all click/action types, drag, creative, break, marked drops,
safe-off waits, full inventories, unchanged blocked contents and successful retry.
Both smoke profiles perform two cold boots, metadata and persistence checks,
malformed reload recovery, lifecycle auditing and clean shutdown with free ports.

Final source/artifact identity, JDK properties, test totals, hashes and smoke
evidence locations are recorded in `.scratch/autosell-20261104/verification.json`.
The named artifact and its `.sha256` sidecar are in `target/`.

Real Java and Bedrock client rendering, physical click timing, and interactions
with the complete live plugin stack still need the normal gameplay approval.
The synthetic probes do not claim that client testing or real economy delivery
has happened. Neither the shared server nor `servers/Paper-26.2/` is modified or
started; this work does not deploy a live release.
